# Changelog

## Unreleased

- The app uses the Crumble icon, as on Android and the website.
- The app's bundle ID is now `ng.crumbli.ios`, matching the Android and macOS apps. Keychain items and the sign-in callback follow it, so it installs as a new app and you sign in again.
- The bot form shows the portrait with a pencil, and the avatar editor opens in a popover instead of filling the form, as on the web.
- Unsent text stays with its chat, including across launches.
- The bot form offers only the reasoning levels its model supports, and suggests models for the desktop job.
- Failed Activity entries show an **Error** badge. Deleting an MCP server asks first.
- The app now reads like Messages. The root is one list of bots and group chats, the latest first, with large portraits, two lines of the latest message, a date, an unread dot, and search and compose at the bottom. A phone opens on this list rather than the first chat.
- **Settings** opens from the top corner and holds the account, theme, notifications, every workspace page, and every connected service. The list no longer has these sections.
- Chats have a centered portrait over the name, blue and gray bubbles with a tail on the last of a run, tighter spacing, and a typing bubble. Tapping the header opens the bot's details, which hold its desktop and, on a phone, its reasoning level.
- The composer's send button sits inside the field and appears when there is something to send. A reply starts with a swipe across a message or a long press, and a swipe from the screen's edge goes back.
- A failed turn is a small line under the conversation, and reactions sit on a bubble's top corner.
- A new **Providers** page lists every provider with its status, set-up providers first, and has a search field. Choose a provider to open its key and sign-in form, which moved here from general settings.
- A provider a command-line tool signs in to, such as Claude Code, shows **Signed in**, **Not signed in**, **Not installed**, or **Unavailable**, and its menu copies the sign-in or sign-out command to run on the server's machine.
- **Integrations** has a search field for names and addresses.
- An MCP server's form has **OAuth App** fields for a client ID and client secret, for servers such as GitHub whose sign-in can't register Crumble. The secret is write-only.
- A memory shows where it came from and how long ago it changed, and a search highlights its matches.
- **Passkeys** in settings lists the account's passkeys, with **Rename** and **Remove**. Add a passkey on the web.
- The app icon shows how many replies you haven't seen while the app was following the server, as the web's tab title does. Opening a chat clears its replies. A device that allowed notifications before this version needs **Badges** turned on in iOS Settings, and Settings says so.
- **Tasks** is now **Automations**, in the sidebar, the bot editor, chat labels, memory sources, and the bot's details, as `bot/GLOSSARY.md` and the web name it.
- Automations are one list across bots with **All**, **Active**, **Paused**, and **Completed** filter pills. Each row shows its kind, readable timing, next run, and status, and its menu has **Run Now**, **Edit**, **Pause** or **Resume**, and **Delete**, which asks first.
- Create and edit script automations, with a command, a timeout, and whether results go to the chat. The Script tab appears for a bot with coding on a server that runs jobs.
- Saving an automation closes its sheet at once. If the server refuses the save, a notice says so and the sheet comes back with what you typed and the reason, after any sheet you've opened since closes.
- The editor stops at the server's limits on a prompt and a command, as on the web.
- Run an automation when an event arrives at an event source, from the new **Time** and **Event** tabs.
- The editor builds repeating schedules from presets (every hour, day, weekday, week, or month) with a **Custom (cron)** choice, and previews the next run.
- The **Runs** tab lists chat and script runs together. A chat run opens its bot's chat and a script run opens its output.
- Fix editing a script or event automation: a script could not be saved at all, and saving an event automation replaced its trigger with a run time an hour away.
- The composer has a reasoning level control beside the message field. It offers the levels the bot's model takes, shows the level turns actually run at, and hides when the model takes fewer than two. A change shows at once and comes back if the server refuses it.
- Return on a hardware keyboard confirms an input method's composition instead of sending it, and tapping Send during a composition clears the field.
- Paste images and files into the composer, from the Paste menu or `⌘V`. The field is now a text view, so Paste appears when the clipboard holds only an image.
- `@` in a bot chat completes every other enabled bot once the bot can message other bots, as on the web, instead of only its allowed bots.
- Send appears beside Stop once you type while the bot is running, so you can send a follow-up without stopping it.
- **Details** in the chat toolbar opens the bot's details: its portrait, desktop, automations with a switch for each except finished one-time runs, model, and memories, beside the chat on iPad and as a sheet on iPhone.
- **Provider Settings…** on a failed turn opens the **Providers** page instead of the Integrations page, which has no providers.
- The bot editor has a **Create bots** capability.
- A chat shows stats, tables, and charts from the `show` tool, and a tap on a chart point opens its tooltip.
- Replies render Markdown tables.
- A chat shows desktop screenshots inline, and a failed job as a card that opens the job.
- Prompts from automations, bot requests, other bots, and credentials collapse into a notice row you can expand, as on the web.
- An owner message that came through a message gateway says **Sent from Discord**.
- Mermaid diagrams in replies draw inline with the server's Pele module, in a web view, on every diagram type the web supports. A diagram that can't be drawn shows as code.
- A jump-to-latest button appears when you scroll up in a chat or group chat.
- The working row says what the bot is doing: **Thinking**, **Writing**, **Searching**, **Remembering**, **Using tools**, or **Retrying**, in place of "Name is working…".
- Add a **Theme** picker to Settings with **System**, **Light**, and **Dark**, as on the web. The theme is saved on your account, so it follows you between devices, and it applies at once; it comes back with the reason if the server refuses it.
- The sidebar gains a search field with the web's command palette: find a bot, a group chat, or a page, create a bot or group chat, open Settings, or change the theme.
- Add Credentials and Logins pages across every bot, with a pill per bot, search, and a bot picker for a new one.
- Add an Avatars page with a bot selector, idle, working, and sleeping previews, and Save.
- **Sign Out** stays off while **Connect** runs, and a connection that finishes after you signed out no longer brings the session back.
- Provider API keys and MCP tokens can come from a connected password manager, and their forms link to connecting one. A new reference holds the form until the server has read it.
- The Activity page has pills per kind, a bot filter that also covers Changes, and Show older activity.
- The gateway sheet has Reset, and Add stays off for credential names reserved for the workspace.
- Show provider, password manager, and gateway logos as on the web.
- Fix MCP tokens, which were sent as a plain string the server refuses.
- Show why a used event source can't be deleted under its name, since a disabled button has no tooltip on touch.

- A reply that waits for you has its own notification sound: one for a held desktop action, another for a credential or login request, the same cues as on the web. A remote push still uses the system sound while the app isn't open, because the server names that sound.
- A local notification now shows while the app is open on another chat. Its payload was missing fields, so it was dropped.
- Bot chats show the pages a reply cited as source links, from what its turn searched or read, as group chats do. A literal `()` in a reply now stays in the text.
- Bot chats show the emoji a bot reacted with on the message it answered.
- Each group keeps what you typed while you visit other chats. A new connection clears these drafts, and closing the app loses them.
- New messages in a group chat rise and fade in, unless **Reduce Motion** is on.
- An expanded job step shows all of its output instead of the last 200 lines.
- Create an account in **Settings**: **Create an Account** asks for your name, email, and password and shows the server's reason if it refuses, such as closed sign-up or a short password.
- Accept an invite link by pasting it into **Server URL**. The link fills in its server, opens **Create Account**, and shows **Link added**. Links can't open the app directly, because that needs each server's domain compiled into it.
- Add **Sign Out** to a new **Account** section in Settings, with your name and email. The app unregisters this device from push first, ends the session on the server, then clears it from this device. If the server can't confirm it, you're still signed out here and a notice says the session may stay active until it expires.
- While signed in, Settings shows the account and the server address with **Connect**, instead of the email and password fields: sign out to change accounts. A session the server no longer knows brings the fields back.
- A push registration whose session ended no longer blocks registering again.
- Passkeys aren't available: an Apple app can only use passkeys for domains compiled into it, which can't include a self-hosted server. A passkey added on the web stays usable there.
- The **Activity** page shows skill and memory changes, groups entries by day as on the web, and gains a **Changes** view you can narrow to one bot. Each change expands to its diff and a **Revert** button that asks first, as on the web. The revert shows as pending until the server records it, and a failed revert rereads the list because it may still have reached the server. A filter on a deleted bot goes back to **All bots**.
- The **Event relay** page in the sidebar gains **Event sources**: add one to get its webhook address, shown once in a sheet that only **Done** closes, and delete one that no automation uses.
- Add **Judge model** and **Vision model** pages, as on the web. Each lists the models your provider keys reach, says what the setting does now, and keeps a chosen model no key reaches as **(no key)**. A choice applies at once and comes back with the reason if the server refuses it.
- The **Web search** page chooses the default provider and warns when Exa has no key.
- The bot editor gains the **Web search** capability, on by default for new bots as on the web, and a **Web search provider** picker with **Account default**, **Mixed**, and **Exa**.
- Signing in to a provider, or saving or removing its key, now also refreshes the open bot editor's model list and the judge and vision choices, not just the provider list.
- Add a **Connected services** group to the sidebar, as on the web. **Password managers** connects 1Password or Bitwarden with a token, which is checked before the sheet closes, replaces a token, and disconnects one no secret reads from. **Web search** holds web search provider keys. **Message gateways** turns a gateway on, sets its token, default bot, aliases, owner, direct messages, and channels, and follows its connection every 5 seconds. **Event relay** sets the relay URL and Doorstep account token and shows the connection status.
- Sheets for a secret offer **Connect a password manager** while none is connected. It opens over the sheet, so what you typed stays, and the sheet can read from the new password manager as soon as you return.
- Add server administration for admins. A **Users** page in the sidebar lists every account with **Make admin**, **Make regular user**, and **Remove account and data**, which asks first; your own account has no actions, so you can't lock yourself out. Changes show at once and come back on failure. **Invite** creates a one-time invite link, shows it once to copy (its copy stays on this device), and lists pending invites with **Revoke**. **Open sign-up** turns sign-up on or off. Accounts that aren't admins don't see the page.
- Add a **Coding** page, as on the web, and move GitHub Apps and machine accounts there from Integrations. Its **Workspaces** section lets admins edit workspace size, coding image, and question grace period, lists running workspaces on another image, and tells every account which server settings coding and desktop jobs still need.
- While an App installs, the app warns that the web page GitHub returns to may say the link is incomplete; the app confirms the installation itself. Install and update skill sheets can't be cancelled or dismissed while the server works, and a failure shows on the sheet.
- Add GitHub Apps to the Coding page: GitHub identities your bots commit and open pull requests as. **New GitHub App** opens GitHub in the system sign-in sheet, which closes itself once the server has the result to create a private App, and **Install** opens its installation page. An App's sheet shows whether it's installed, checks again, signs you in so bots act as you, signs you out, takes a client secret, and turns bots on or off. Bot changes show at once and reopen the sheet on failure; removing asks first, applies at once, and comes back on failure. Steps on GitHub show as pending until the server confirms them.
- GitHub returns to the server's web page, not the app, so that page finishes creating an App and signing in. Sign in to it in your browser first: if you aren't, GitHub's answer is lost, and an App GitHub created has to be deleted on GitHub before you try the name again.
- Add machine accounts to the Coding page: GitHub users your bots act as wherever none of their GitHub Apps does. **New Machine Account** takes a personal access token, or a reference when a password manager is connected, and shows **Saving…** until the server confirms GitHub accepts it; a refusal keeps the sheet. An account's sheet turns bots on or off, replaces the token, opens the account on GitHub, and copies its signing key. Bot changes show at once and reopen the sheet on failure. Removing asks first, applies at once, and comes back on failure. Saved tokens never show again, and typed tokens are dropped when the sheet closes.
- Finish shared skills. **Install from GitHub** lists the skills in a public repository or a folder link, shows which are installed or can't be installed and why, and turns the chosen ones on for the bots you pick. An installed skill is read-only: its row opens the skill with its source, instructions, and reference documents, **Used by**, and **Make a copy**, which creates an editable shared skill with the same description and documents. **Check for Updates** reports repositories it couldn't read, and rows show **Update available** or **Removed upstream**. **Review update** shows what would change, and the update shows as done only once the server confirms it.
- The Skills page searches by name and instructions, filters by owner with **Whose skills**, and lists bots' own skills and **Default** skills in sections of their own. Checkboxes select one skill, a section, or every result, for bulk **Update**, **Assign to bots**, **Remove from bots**, and **Delete**. A report names each skip and failure, failed skills stay selected, and deleted skills leave at once and come back if the server refuses.
- The shared skill form gains **Used by**, applied when you save, in place of the per-bot controls on the row. A shared skill's row opens its form, and deleting asks first. Skill forms stop at the server's name and instructions limits.
- The skill form gains **Available to**, so a new skill can belong to one bot.
- Add a bot's own skills to the bot editor: list them, add or edit one in the skill form, pin or unpin it, and delete it after a confirmation. **Shared Skills** there turns a shared skill on or off for the bot at once. Changes show immediately and come back on failure; a failed save reopens the form with what you typed. A bot added while the list is open loads its own skills.
- The Skills workspace edits bot skills the same way, so renaming one keeps its documents, usage, and pin. Saving the bot editor no longer sends skills or shared skill assignments, so it can't remove a skill a bot added while the editor was open. Shared skill assignment changes one bot and one skill at a time.
- Add per-bot credentials and logins to the bot editor. **Credentials** and **Logins** list what is saved, with hosts and last use, and what the bot asks for; a row opens **Edit**, and its menu offers **Uses** or **Fills** and **Delete…**. GitHub tokens only show their uses. New entries take a value, or a reference when a password manager is connected, and a login can use a 1Password item and a one-time code. Saved values never show again: **Keep the saved value** stands in for them, and typed values are dropped when the sheet closes. A save shows in the list at once, and a refusal takes the row back and reopens the sheet with what you typed. A save with a new password manager reference instead shows **Saving…** on the sheet, with **Cancel** off, until the server has read it; a refusal keeps the sheet. Deleting applies at once and comes back on failure.
- A bot's request for a credential or login shows as a card in its chat with **Add Credential** or **Add Login** and **Decline**. **Add** opens the sheet with the bot's reason and proposed hosts. The card settles as **Saved** or **Declined** once the server confirms it, including from another client. The notice the bot gets reads **Credential · NAME**.
- Approve, edit, or decline a bot request in the bot's chat. The card shows the proposed bot's avatar, name, model, description, and capabilities; **Edit** opens the proposal in the bot editor, including its avatar, and **Approve** there creates the bot as edited. A request shows as approved only once the server confirms it: a refusal keeps the card with the error, and a request decided elsewhere settles. The new bot joins the sidebar, and **Open Chat** on the card opens it.
- Approve or decline a desktop job action an intent check held, in the bot's chat. The card names the job, the action, its page, and why it was held, and shows the messages it was checked against. An action shows as approved only once the server confirms it: a refusal keeps the card waiting with the error, and an action decided elsewhere settles as **Approved**, **Declined**, or **Expired**.
- Add provider account sign-in to Settings, such as ChatGPT, Codex, or Claude. **Providers** shows what is saved and offers each provider's sign-ins next to its API key, with **Sign Out** for an account. **Open Sign-In Page** and device-code links open in the system sign-in sheet, which closes when the server finishes; **Open in Safari** and **Copy Link** are for a browser with an address bar. The app answers the provider's questions, shows success only once the server saved the sign-in, picks up a sign-in running on the server, and **Cancel Sign-In** ends it. A blank answer is allowed for text questions, so GitHub Copilot can use github.com.
- Add coding jobs and desktop job cards. A job a bot starts shows as a card in the chat that opens its task, replies, and tool steps, with its model and spend, **Download Transcript**, and earlier activity. Tap a step for its output. A desktop job's panel opens the bot desktop. Job reports stay behind their card, as on the web.
- Answer a coding job's question in the chat or on the job's panel: pick an option or write an answer. An answer that fails keeps what you wrote.
- The bot editor gains the **Coding** toggle, shown when the server can run coding jobs.
- Add group chats. The sidebar lists them under **Group Chats**; create one with **New Group Chat** from two to six bots, edit it from its toolbar or row, and delete it from its row or the editor after a confirmation. A group shows each bot's messages with its name and avatar, source links for pages it read, reactions beside the message they answer, which bots are answering or disabled, failed turns, and when the bots are paused waiting for you. Messages appear at once and reconcile with the server; failed ones keep their draft and offer **Retry**. `@` completes the group's members, replies and attachments work as in a bot chat, the stop button ends every bot's turn in the group, and the chat catches up when you return from the background. Group answers notify as "Ada in Trip" unless the group is on screen, and a tapped notification opens the group.
- Add the bot desktop. **Bot Desktop** in the chat toolbar opens it over the whole screen, with **Take Control** and **Hand Back**, **Reconnect**, and the reason when the server can't show it, such as a server without a desktop image. Control changes only when the server confirms; leaving the bot desktop or sending the app to the background hands control back, within the time iOS allows and while the server is reachable, and returning reconnects the viewer. With control, touch is the mouse: tap to click, drag to select, touch and hold to right-click, and drag with two fingers to scroll. **Keyboard** opens a field that sends its text to the bot desktop, plus Esc, Tab, arrow, Return, and Delete keys.
- The bot profile shows a live, watch-only preview of a bot's desktop that opens the full one, or **Sleeping** with tap to wake. A desktop job's notification opens the bot desktop.
- The bot editor gains the **Bot desktop** toggle, shown when the server has a desktop image, with an optional desktop job model. Saving a bot in the iOS editor used to remove its `desktop` and `coding` tools and any other tool without a toggle; it now keeps them.
- Bots show the avatar stored on the server, rendered with Open Bot Avatar, instead of a face seeded from their ID: `.thinking` while working and dimmed and still while paused. The bot editor gains the web app's avatar editor: body and eye colors, a gallery of 22 shapes, **Import** of a definition's JSON, and **Generate**, which copies a design prompt. The choice saves when you create or update a bot.
- Sign in with account email and password in Settings; the app stores the returned session.
- Build against bot contract 6.0.0. The bearer token must be an account session token from `POST /api/auth/sign-in/email`; the old server token is rejected.
- CI runs SwiftLint in its own job, beside the build.
- New bots start with **Schedule tasks**, **Message other bots**, and **Code mode** on, besides **Memory**, and may message every existing bot.
- Move into the `crumble-project/apple` repository and reference `../apfelkern` as a local package instead of a pinned revision. This adopts apfelkern through bot contract 1.6.0.
- CI only builds the app and its tests with cached Swift packages and build products; tests need a simulator and run locally. `scripts/build.sh` runs the CI build, and `scripts/test.sh` accepts `unit`, `ui`, or `all`.
- Replace the local glossary with a link to the canonical glossary in the spec repository.
- Remove references to the obsolete agent folder field, as required by the current shared package and server contract.
- Adopt apfelkern's generated API operations, shared activity and push models, and event decoding without an app-local generator.
- Pin apfelkern by commit over HTTPS and run unsigned simulator tests in public-repository CI.
