# Changelog

## Unreleased

- The **Activity** page shows skill and memory changes, groups entries by day as on the web, and gains a **Changes** view you can narrow to one bot. Each change expands to its diff and a **Revert** button that asks first, as on the web. The revert shows as pending until the server records it, and a failed revert rereads the list because it may still have reached the server. A filter on a deleted bot goes back to **All bots**.
- The **Event relay** page in Settings gains **Event sources**: add one to get its webhook address, shown once in a sheet that only **Done** closes, and delete one that no automation uses.
- Add **Judge model** and **Vision model** pages, as on the web. Each lists the models your provider keys reach, says what the setting does now, and keeps a chosen model no key reaches as **(no key)**. A choice applies at once and comes back with the reason if the server refuses it.
- The **Web search** page chooses the default provider and warns when Exa has no key.
- The bot editor gains the **Web search** capability, on by default for new bots as on the web, and a **Web search provider** picker with **Account default**, **Mixed**, and **Exa**.
- Signing in to a provider, or saving or removing its key, now also refreshes the open bot editor's model list and the judge and vision choices, not just the provider list.
- Add a **Connected services** group to Settings, as on the web. **Password managers** connects 1Password or Bitwarden with a token, which is checked before the sheet closes, replaces a token, and disconnects one no secret reads from. **Web search** holds web search provider keys. **Message gateways** turns a gateway on, sets its token, default bot, aliases, owner, direct messages, and channels, and follows its connection every 5 seconds. **Event relay** sets the relay URL and Doorstep account token and shows the connection status.
- Sheets for a secret offer **Connect a password manager** while none is connected. It opens over the sheet, so what you typed stays, and the sheet can read from the new password manager as soon as you return.
- Add server administration for admins. A **Users** page in Settings lists every account with **Make admin**, **Make regular user**, and **Remove account and data**, which asks first; your own account has no actions, so you can't lock yourself out. Changes show at once and come back on failure. **Invite** creates a one-time invite link, shows it once to copy (its copy is marked so clipboard managers leave it out of their history), and lists pending invites with **Revoke**. **Open sign-up** turns sign-up on or off. Accounts that aren't admins don't see the page.
- Add a **Coding** page, as on the web, and move GitHub Apps and machine accounts there from Integrations. Its **Workspaces** section lets admins edit workspace size, coding image, and question grace period, lists running workspaces on another image, and tells every account which server settings coding and desktop jobs still need.
- While an App installs, the app warns that the web page GitHub returns to may say the link is incomplete; the app confirms the installation itself. Install and update skill sheets can't be cancelled or dismissed while the server works, and a failure shows on the sheet.
- Add GitHub Apps to the Coding page: GitHub identities your bots commit and open pull requests as. **New GitHub App** opens GitHub in your default browser; **Stop Waiting** ends the wait to create a private App, and **Install** opens its installation page. An App's sheet shows whether it's installed, checks again, signs you in so bots act as you, signs you out, takes a client secret, and turns bots on or off. Bot changes show at once and reopen the sheet on failure; removing asks first, applies at once, and comes back on failure. Steps on GitHub show as pending until the server confirms them.
- GitHub returns to the server's web page, not the app, so that page finishes creating an App and signing in. Sign in to it in your browser first: if you aren't, GitHub's answer is lost, and an App GitHub created has to be deleted on GitHub before you try the name again.
- Add machine accounts to the Coding page: GitHub users your bots act as wherever none of their GitHub Apps does. **New Machine Account** takes a personal access token, or a reference when a password manager is connected, and shows **Saving…** until the server confirms GitHub accepts it; a refusal keeps the sheet. An account's sheet turns bots on or off, replaces the token, opens the account on GitHub, and copies its signing key. Bot changes show at once and reopen the sheet on failure. Removing asks first, applies at once, and comes back on failure. Saved tokens never show again, and typed tokens are dropped when the sheet closes.
- Finish shared skills. **Install from GitHub** lists the skills in a public repository or a folder link, shows which are installed or can't be installed and why, and turns the chosen ones on for the bots you pick. An installed skill is read-only: its row opens the skill with its source, instructions, and reference documents, **Used by**, and **Make a copy**, which creates an editable shared skill with the same description and documents. **Check for Updates** reports repositories it couldn't read, and rows show **Update available** or **Removed upstream**. **Review update** shows what would change, and the update shows as done only once the server confirms it.
- The Skills page searches by name and instructions, filters by owner with **Whose skills**, and lists bots' own skills and **Default** skills in sections of their own. Checkboxes select one skill, a section, or every result, for bulk **Update**, **Assign to bots**, **Remove from bots**, and **Delete**. A report names each skip and failure, failed skills stay selected, and deleted skills leave at once and come back if the server refuses.
- The shared skill form gains **Used by**, applied when you save, in place of the per-bot controls on the row. A shared skill's row opens its form, and deleting asks first. Skill forms stop at the server's name and instructions limits.
- Add a bot's own skills to the bot editor: list them, add or edit one in the skill form, pin or unpin it, and delete it after a confirmation. **Shared Skills** there turns a shared skill on or off for the bot at once. Changes show immediately and come back on failure; a failed save reopens the form with what you typed. A bot added while the list is open loads its own skills.
- The Skills workspace edits bot skills the same way, so renaming one keeps its documents, usage, and pin. Saving the bot editor no longer sends skills or shared skill assignments, so it can't remove a skill a bot added while the editor was open. Shared skill assignment changes one bot and one skill at a time.
- Add per-bot credentials and logins to the bot editor. **Credentials** and **Logins** list what is saved, with hosts and last use, and what the bot asks for; a row opens **Edit**, and its menu offers **Uses** or **Fills** and **Delete…**. GitHub tokens only show their uses. New entries take a value, or a reference when a password manager is connected, and a login can use a 1Password item and a one-time code. Saved values never show again: **Keep the saved value** stands in for them, and typed values are dropped when the sheet closes. A save shows in the list at once, and a refusal takes the row back and reopens the sheet with what you typed. A save with a new password manager reference instead shows **Saving…** on the sheet, with **Cancel** off, until the server has read it; a refusal keeps the sheet. Deleting applies at once and comes back on failure.
- A bot's request for a credential or login shows as a card in its chat with **Add Credential** or **Add Login** and **Decline**. **Add** opens the sheet with the bot's reason and proposed hosts. The card settles as **Saved** or **Declined** once the server confirms it, including from another client. The notice the bot gets reads **Credential · NAME**.
- Approve, edit, or decline a bot request in the bot's chat. The card shows the proposed bot's avatar, name, model, description, and capabilities; **Edit** opens the proposal in the bot editor, including its avatar, and **Approve** there creates the bot as edited. A request shows as approved only once the server confirms it: a refusal keeps the card with the error, and a request decided elsewhere settles. The new bot joins the sidebar, and **Open Chat** on the card opens it.
- Approve or decline a desktop job action an intent check held, in the bot's chat. The card names the job, the action, its page, and why it was held, and shows the messages it was checked against. An action shows as approved only once the server confirms it: a refusal keeps the card waiting with the error, and an action decided elsewhere settles as **Approved**, **Declined**, or **Expired**.
- Group chat logic moves to `GroupChatHost` in apfelkern, shared with iOS. Retrying a failed group message now clears the draft the failure restored, so pressing Return can't send it twice.
- Provider sign-in state moves to `ProviderLoginBoard` in apfelkern, with no change in behavior.
- Answer a coding job's question in the chat or on the job's panel: pick an option or write an answer. While the job waits, the box stays up to date, and once it is answered, by you or by the bot that delegated the task, the chat shows it as answered. An answer that fails keeps what you wrote.
- The job panel follows a working job's steps every few seconds, names the job's model in its title, and downloads the whole transcript as Markdown with **Download Transcript**. A zero cost, which subscription providers report, no longer shows.
- Group chats catch up with the web app. Deleting a group asks first, from its context menu or from a new **Delete Group…** in the editor, and a failed deletion reopens the group. Bot messages show source links for the pages their turn read instead of inline citations. Turns that only called tools no longer leave an empty bubble, a failed turn of a deleted bot still shows, replying to a bot names it instead of "Agent", group names stop at 80 characters, and an empty **Group Chats** section says what to do next.
- `BotDesktopSession` moves to apfelkern. The bot desktop window offers **Take Control** only once the server has reported who holds control, disables **Reconnect** while connecting, and hands back a take that the server confirms after the window closed.
- Bots show the avatar stored on the server, rendered with Open Bot Avatar, instead of a face seeded from their ID. The bot editor gains the web app's avatar editor: body and eye colors, a gallery of 22 shapes, **Import** of a definition's JSON, and **Generate**, which copies a design prompt. The choice saves when you create or update a bot.
- As on the web and iOS, only paused bots show as sleeping, dimmed and still. Bots you aren't viewing used to sleep too; in the sidebar they now hold still at full strength, and only the open and working bots animate.
- Remove the `AvatarPlayground` target and the `--finishes`, `--snapshot`, and benchmark commands; they only exercised the old renderer.
- Sign in with account email and password in Settings; the app stores the returned session.
- Build against bot contract 6.0.0. The bearer token must be an account session token from `POST /api/auth/sign-in/email`; the old server token is rejected.
- CI runs SwiftLint in its own job, beside the tests.
- New bots start with **Memory**, **Schedule tasks**, **Message other bots**, and **Code mode** on, and may message every existing bot. The profile's capability toggles each carry a one-line description instead of one long footer.
- **Skills** and **Integrations** show one list instead of a **Shared** section plus one per bot; each row names its scope. **New Skill** (formerly **New Shared Skill**) and **Add MCP Server** (formerly **Add Shared MCP Server**) choose the scope in the form.
- Sign in to provider accounts, such as ChatGPT, Codex, or Claude, under **Providers** in Settings (formerly **Provider API Keys**). The server runs the sign-in; the app shows its steps: **Open Sign-In Page** for a link, a device code with **Copy Code**, and questions such as pasting the address the browser ended on. Sign-in continues after a lost connection, shows success only once the server saved the credential, and reports failure, cancellation, and expiry. Settings shows whether the provider has a saved API key or account sign-in, and **Sign Out** removes an account sign-in. Needs bot contract 1.7.0.
- Move into the `crumble-project/apple` repository and build against `../apfelkern` by path. The apfelkern revision pin and `APFELKERN_LOCAL` are gone. Remove the signed and notarized nightly build and its `nightly` pre-release workflow; `build-app.sh` still signs with `CRUMBLE_SIGNING_IDENTITY`.
- Add desktop jobs. The bot editor's **Bot desktop** toggle gives a bot its own bot desktop, with an optional desktop job model (empty uses the bot's model). Desktop jobs show as cards in the chat like coding jobs, and both kinds of job sheet show the job's tokens and cost. **Bot Desktop** in the chat toolbar or a desktop job's sheet opens the bot desktop in its own window, with **Take Control** and **Hand Back**; control changes only when the server confirms, and closing the window while you hold control hands it back. A bot's answer to a job's report notifies titled with the job, such as "Desk · desktop job github", and a desktop job's notification also opens the bot desktop.
- Pin apfelkern to its desktop job release, which uses bot contract `contract-v1.6.0`. Servers before contract 1.4.0, which do not report the `desktop` capability, show no Coding toggle for bots without coding.
- Add group chats. The sidebar lists them under **Group Chats**; create one with **New Group Chat** (⇧⌘N) from two to six bots, and edit or delete it from its context menu or toolbar. A group shows each bot's messages with its name and avatar, reactions beside the message they answer, which bots are answering or disabled, failed turns, and when the bots are paused waiting for you. Messages appear at once and reconcile with the server; `@` completes the group's members, replies and attachments work as in a bot chat, and the stop button ends every bot's turn in the group. Group answers notify as "Ada in Trip" unless the group is on screen, and a click opens the group. Pin apfelkern to its group chat release, which uses bot contract `contract-v1.3.0`.
